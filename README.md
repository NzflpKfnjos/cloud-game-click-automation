# 云游戏点击脚本助手

这是一个 Tampermonkey 用户脚本，用于在腾讯云游戏网页画布上记录和重放点击位置。

## 安装

1. 打开 Tampermonkey 的脚本管理页。
2. 新建用户脚本，将 `cloud-game-click-automation.user.js` 的内容粘贴进去。
3. 保存后刷新云游戏页面。

首次加载会按当前游戏载入默认配置：金铲铲 3 个坐标、间隔 100 毫秒；火影忍者 11 个坐标、间隔 50 毫秒。脚本会把坐标按画布比例保存，画布尺寸变化后仍可复用。重连恢复任务时会沿用任务的坐标与剩余轮数。

## 使用

- `记录`：点击游戏画面添加坐标，再点击一次结束记录。
- `运行`：按顺序执行坐标点击。
- `停止`：中止当前运行。
- `间隔(ms)`：相邻坐标之间的等待时间。
- `循环(0=无限)`：执行轮数，0 表示持续运行。
- `清空坐标`、`导出`、`导入`：管理坐标配置。
- 快捷键：F8 运行/停止，F9 开始/结束记录，Esc 停止。

## 重新连接

- 页面首次打开或切换游戏时加载当前游戏的 iframe。
- 点击 `重新连接` 会立即重新加载当前游戏的 iframe。
- 页面不会按固定时间自动刷新。用户脚本会每 5 秒检查视频显示帧、WebRTC 接收/解码进度和画布绘制状态；确认连续 30 秒无进展后，先尝试恢复播放、ICE 连接或 WebGL 上下文，再等待 10 秒，仍无进展时重新加载当前 iframe。
- 后台、离线、主动暂停播放，以及尚未观察到正常视频进度的页面不自动重连；单独静止的画布内容不会触发恢复。画布绘制已正常推进且云游戏接收仍持续时，绘制停止也会触发恢复。
- 自动重连至少间隔 60 秒，10 分钟内最多 3 次。达到上限时页面提示手动重连；点击“重新连接”会重置重试次数。直接打开云游戏网址时，脚本在相同限制下重新加载当前页面。
- 用户脚本不提供应用切换下拉，会根据当前网页 URL/hash 中的游戏 ID 自动选择配置。
- 同一款游戏重新加载后，用户脚本会在画布出现时恢复之前正在运行的点击任务；自动恢复会保留任务坐标与剩余轮数（正在执行的那一轮重新开始）。手动停止或切换游戏会清除恢复意图。
- 画布消失时暂停画布坐标的点击并等待恢复，避免坐标退回整个窗口。

> 请同时更新 `index.html` 和 Tampermonkey 用户脚本（1.7.1），并允许脚本在 iframe 中运行。更新脚本后刷新云游戏页面，让它在平台创建连接前安装监测。

## 验证

运行 `node --test tests/*.test.cjs` 检查停帧恢复、后台/离线保护、恢复任务、重连协议和点击行为。测试无需额外依赖。

## 卡顿诊断日志

页面和用户脚本使用同名 `localStorage` 键 `cloud-game-click-diagnostics-v1`，但由于来源不同分别存储：外层页面保留最近 2000 条，云游戏脚本保留最近 3000 条。记录包含页面/脚本会话、iframe 加载与错误、网络和可见性变化、WebRTC 状态与视频/画布进度、恢复尝试、未捕获异常、长任务、事件循环延迟、内存快照、点击运行步骤和恢复意图；刷新页面不会清除这些记录。

关键故障日志自动开启，单独存放在 `cloud-game-click-incidents-v1`，每个来源保留最近 200 条。详细记录关闭时仍保存停帧前约 60 秒的采样证据、恢复尝试及结果、异常、视频状态变化、画布消失和重连决定。普通点击日志不会覆盖这些故障记录。重复错误会限流；存储不可用时当前页面的内存副本仍可导出，关闭页面后则无法保留。

再次卡住时点击页面顶部的“导出诊断日志”（或脚本面板的“导出日志”），将下载的 JSON 发给维护者即可；自动重连前的故障证据也会保留。需要更完整的点击和常规运行记录时，提前点击“开始记录日志”。导出格式版本为 2，包含 `importantRecords`（关键故障）、`records`（详细记录）、当前画面证据、浏览器环境与会话标识。外层页面保留原 iframe 的时间和会话标识，并关联重连后的新会话。若页面完全无法点击，可在开发者工具 Console 执行（只导出当前来源的存储记录）：

```js
copy(JSON.stringify({
  records: JSON.parse(localStorage.getItem('cloud-game-click-diagnostics-v1') || '[]'),
  importantRecords: JSON.parse(localStorage.getItem('cloud-game-click-incidents-v1') || '[]')
}))
```

`stream-stall-detected` 保存故障前采样，包括各阶段计数、增量、距离最后进展的时间、视频播放状态、实际画布尺寸与点击任务状态。`stream-recovery-action` 区分恢复操作的尝试、完成、失败或不支持（操作完成不代表画面已恢复）；`stream-recovery-resolved` 与 `host-recovery-outcome` 记录是否真正收到新帧。`rtc-stats-timeout` / `rtc-stats-error` 表示采集器自身失败；`host-recovery-decision` 记录重连执行或因后台、离线、冷却、重试上限而延后。缺失指标为 `null`，不表示断线。URL 参数、片段与凭据信息会脱敏，日志不采集 SDP、候选地址或视频像素。

详细日志默认关闭，关键故障日志始终保留。点击“开始记录日志”（用户脚本中为“开始日志”）后显示绿色记录状态；再次点击只停止详细记录。刷新后保留日志与记录开关。自动恢复不依赖日志开关，页面通过消息汇总 iframe 诊断。某些自定义或工作线程渲染器不能提供可验证的绘制进度，此时仍监测 WebRTC 接收，但无法保证识别所有渲染冻结。
